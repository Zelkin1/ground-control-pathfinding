## Original game
Movement triggers: player move/queued move/move-with-facing/attack/formation-change; next queued order after current arrival; stance AGGRESSIVE=attack/chase visible enemy, CHICKEN=random escape ≤100m, NORMAL=shoot only. Computer squads: mission scripts; idle go-to/patrol/random-point/wander/follow; counterattack attacker of protected unit within last 2s; sideways step every 1s when unable to fire at target.
Routing: one route from the front unit (member nearest destination); weighted A* spread over ticks, over corners of blocking terrain outlines, 1024×1024 grid, 6.25m cells, heuristic weight 1.5, 60 expansions/tick (search budget), cap 500. Member k→final parking position k (reverse order on turnaround; no matching to the nearest final parking position). Each member searches to route corner 2 (budget 200), follows shared base game waypoints, drives to its final parking position (the last waypoint) without search. Arrival=all stopped OR 20s after all but one stop. Formation layout faces start→destination.
Tick: (1) skip to later visible waypoint/repath hidden current; (2) throttle=0 waiting/turning toward waypoint, 0.5 if waypoint behind, otherwise 1, reduced near the final parking position to ≥0.6; (3) steer (`steer_to`: 1−cos⁶ of heading error, full lock beyond 90°) + base game avoidance (AvoidUnits) bias (drive/wait 2s/full-lock avoidance turn); (4) turn at ω×steering, apply full friction/speed cap, integrate; (5) collision push out of units, blocking terrain slide, slope rescue off excessive slopes. Full friction nearly cancels acceleration, so throttle <~0.9 brakes. Movement runs once per rendered frame with measured frame time; fixed-step mode 0.04s.
Failure causes: 500 cap→"Movement denied" on long/complex routes; 60/tick→reaction lag. Queued moves, formation changes, attacks and all AI moves search all 500 within one tick→hitches. Coarse corner paths/zero-width edge rays (only corners have the 2r corner gap)→hugging blocking terrain/zigzags. `Mover::SetReachMid` 0x50ee40 ignores argument→intermediate reach=1 m; waypoint behind→half throttle→hard braking/circling. Nearest-destination front unit + budget-200 joins + unsearched drives to the last waypoint→stragglers; arrival timeout leaves them. Successful repath→turn on the spot; blocking terrain slides flip the avoidance turn side→stop/go. Moving friend deemed "will clear"→crossing/oncoming squads drive into each other, collision-push through.

## Key contracts
- Image: no relocations, fixed base 0x400000, MSVC6 `thiscall`.
- Grid: 1024×1024 cells, 2 bits each, at 0x6eb47c, 6.25 m/cell; cell blocks a unit when `value > moverClass` (its terrain class); value 2 (hills) blocks tanks (terrain class 1) not infantry (class 2); 3 (cliffs) blocks everything; class 4 aircraft. `PathFinder::LoadGrid` (0x4e8200) is the only grid writer→static per map; stores file's last row as grid row 0.
- Search roles: `StartSearch` (backward search): target=unit, root=destination; `StartSearchQuiet` (forward search) swaps them.
- Success output: open-list head is a node at the target whose `parent` chain leads to the root. Every node must come from the game's `operator new` (0x5e89be) and go into the open list (insert 0x4eba70), so `Reset` frees it.
- Floating point: game sets x87 precision mode→hooked code compiled with `-msse2 -mfpmath=sse` keeps full precision.

## Formation following (form + coord)
- Avoidance (`avoidance.c`): ORCA (RVO2 velocity-obstacle method), nearest desired velocity collision-free over a short horizon; moving pairs share the effort, arrived or turning units are avoided fully, squad mates only near contact. Blocking terrain remains physics (ORCA blocking-terrain constraints fight base game routes that run along blocking terrain); a new velocity is accepted only if the next moment is clear; units kept waiting by the avoidance bypass it for a while.
- Parked squads: `stamp_parked` stamps cells under parked units as cliffs during search; `is_in_sight` hides lines through parked units → routes go around them. Collision push moves only the moving unit; parked units never move for other squads (user: "parked units should not move"; the dodge `--yield` was removed 2026-11-16, see Rejected features); an arrived member of a still-moving squad steps aside for the other members (`step_aside_for_members`).
- Route origin: base game route starts at the front unit (member nearest the destination); recentered on the formation if the onward path is clear; shortened by skipping route corners where a band as wide as the widest member is clear (removes corners and backtracking that swung every slot around). `take_shorter_centered_route` (route.c; no switch since 2026-11-16 (user), was `--centersearch`; user: `headonvalleys` seed 93 squad "goes in a completely wrong direction at first"): centered game search (second base game path search from the members' center), kept if clearly shorter. Cause: the base game path search adds corners around the first blocking terrain on the line to the destination → the start point decides which way around blocking terrain (seed 93: L-route, +67m).
- `smooth_route` (smoothing.c, `--smooth off`; user wanted smooth curves, not kinked bumps): cubic B-spline whose control points are displaced away from blocking terrain toward formation clearance → wide gentle bends, parallel lanes rather than local bulges at blocking terrain. Keeps the whole unsmoothed route if any curve position lacks body clearance (few routes, tight cliff tips; heavies' `corridor` route always); partial blending did worse.
- `widen_bends` (smoothing.c, `--widebends off`; part of `--smooth` with its own toggle (user 2026-11-16: "--widebends should be part of smooth, but keep its toggle"; acts only with `--smooth on`); user: "avoid turns that force units to slow down before turning, favor wider turns"): second stage of `smooth_route`, after its displacements and only when the body clears; spreads bends sharper than the full-speed minimum radius + formation half-width; best iteration kept.
- Formation (user 2026-11-16: "--formation should control anchor as well ... There should not be anchor without formation"; `--formation`, was "Places" and `--reassign`; the switch holds anchor lag waiting, slot swaps, ahead slowdown and wait ahead (below); `--formation off` = all four off: the anchor drives at the top speed of the squad and ignores laggards (new off-state, so `--formation off` output differs from the old `--reassign off --aheadslow off --waitahead off`; defaults identical)).
  - Anchor (point that moves along the route, `advance_anchor`, formation.c; always on): top speed of the squad when together; slows with lag, crawls beyond a larger lag, stops beyond a very large one; ignores lag for a while after waiting (one stuck unit cannot make it wait forever); turns slow it only through the lag (`--turnslow` removed, see Rejected features).
  - Slots: the first permutation of the final parking positions among the members minimizes total squared distance (keeps the arrangement). Slot swaps (`swap_slots`, formation.c; one logic for all swaps since 2026-11-16 (user: "optimize distance to travel to reach goal by switching positions in formation. Preserve the current behavior"; `--reformmatch` merged in; output identical, see Simulator "Switch clean-up")): members swap slots so their ways to their slots stay short; measure by part of the route:
    - On the way: periodic slot swap in route coordinates (side weighted), only when clearly better. Most pairs keep left/right and front/back; plain distances do not keep order; a larger side weight worsens everything else.
    - After column formation (reforming swap; was `--reformmatch`, 2026-11-15; replaces the removed `--regroup`/`--closeup`, see Rejected features; user: "revert to the old formation switch, but make it smarter ... the position of each unit in the squad is dynamically adjusted to minimize reformation time"; user example: corridor seed0 t≈25, medium squad; kept (user: "Keep it")): on leaving column formation and while reforming, the largest catch-up cost is smallest (the squad waits for its slowest member). The largest catch-up is fixed by geometry (last member to the rear row), so gains come from sideways moves and inner sides of bends. 100 seeds, C, off→on: faster (corridor most, then headonvalleys, ridge), slightly more stops (infantry) and slow time, more slot swaps, rest about equal.
    - End section of the route (with `--driving`, was `--endstop`): one final swap member→final parking position by squared distance at the start of the end section, then frozen (a new final parking position on the end section made units stop and turn around).
- Lanes (`set_up_lanes`/`get_lane_point`, lanes.c; per-member lanes (user), `--lanes off`): slot side offsets fitted to the free width along the route, planned over the whole route (early response to blocking terrain, handles cliff islands); lanes may merge, never cross (user; `simulator/tools/check_lanes.py` verifies a trace). One shared route instead: far more blocking terrain slides than the game.
